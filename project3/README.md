## Как запустить

> **Важно.** `os.fork`, `strace` и `ps` работают только в Linux. На Windows используйте **WSL**
> (встроенный в Windows Linux). Обычный PowerShell/cmd для этих заданий не подходит.

### 1. Один раз: установить WSL
1. Откройте **PowerShell от имени администратора** (правый клик по «Пуск» → «Терминал (администратор)»).
2. Выполните: `wsl --install` и перезагрузите компьютер.
3. После перезагрузки откроется окно Ubuntu: придумайте имя пользователя и пароль
   (при вводе пароля символы **не отображаются** — это нормально).
4. В окне Ubuntu выполните: `sudo apt update && sudo apt install -y strace python3`

### 2. Открыть папку проекта в WSL
В Проводнике Windows откройте папку проекта, нажмите на адресную строку, введите `wsl` и Enter.
Откроется терминал уже внутри этой папки. (Или вручную: `cd /mnt/c/Users/ИМЯ/Downloads/project3`.)

### 3. Запустить всё сразу
```bash
bash run_all.sh
```
Займёт около минуты. Все результаты окажутся в папке `results/`.

### Или по отдельности

### Проверка Ctrl+C вручную (задание C2)
```bash
python3 advanced.py --method shm -n 4 --delay 1     # --delay замедляет работу, чтобы успеть
# пока работает — нажмите Ctrl+C
ps -eo pid,ppid,stat,comm | grep -E "python3| Z"    # ничего лишнего: процессов и зомби нет
ls /dev/shm                                          # нет файлов psm_*
ls /tmp | grep logs_                                 # нет временных папок logs_*
```

### Команды для замеров (задания A2 и C1; `run_all.sh` делает это сам)
```bash
strace -c -S calls wc -l logs/access_01.log
strace -c -S calls python3 count_one.py logs/access_01.log
strace -f -c -S calls python3 advanced.py --method pipe -n 4 --quiet
```
`-c` — сводка по системным вызовам, `-S calls` — сортировка по числу вызовов, `-f` — следить и за дочерними процессами.

## Объяснения (что спросят на защите)

**Что такое `fork`?** Системный вызов, который создаёт копию текущего процесса. После него
работают два процесса с одинаковым кодом; `os.fork()` возвращает ребёнку `0`, а родителю — PID
ребёнка. По этому значению код понимает, «кто я».

**Что такое `pipe`?** Труба в ядре: один конец для записи, другой для чтения. Ребёнок пишет
результат в один конец, родитель читает из другого. Родитель обязательно закрывает у себя
конец для записи: иначе `read` никогда не получит «конец данных» и будет ждать вечно.

**Что такое зомби?** Ребёнок уже завершился, но родитель ещё не вызвал `waitpid`, и в таблице
процессов осталась запись о нём (в `ps` статус `Z`). Поэтому родитель всегда вызывает
`os.waitpid` для каждого ребёнка — даже при ошибке и при Ctrl+C (блок `finally`).

**Зачем `os._exit` в ребёнке?** Обычный `sys.exit` в ребёнке запустил бы код завершения,
унаследованный от родителя (очистку буферов и т.п.). `os._exit` завершает ребёнка сразу и тихо.

**Почему `wc -l` быстрее Python-подсчёта?** `wc` — маленькая программа на C: читает файл
большими блоками и считает символы перевода строки. Python сначала запускает интерпретатор
(много системных вызовов на загрузку модулей), читает файл небольшими порциями и создаёт
объект-строку для каждой из 15 000 строк. Реальные цифры (138 против 515 системных вызовов) — в REPORT.md, раздел 6.

**Три способа вернуть результат:**
- `pipe` — данные идут через буфер ядра; синхронизация «бесплатная» (конец данных = закрытие трубы).
- `shared_memory` — общий участок памяти, копирования через ядро нет, но нужен свой протокол
  (у каждого процесса свой слот + длина данных) и ручная очистка (`unlink`) сегмента в `/dev/shm`.
- временные файлы — самый универсальный и «тяжёлый» способ (открытие, запись, переименование,
  чтение, удаление); данные переживают падение процесса, но надо следить за очисткой каталога.

**Что происходит при Ctrl+C?** Терминал посылает `SIGINT` *всей группе процессов* — и родителю,
и детям. Дети просто умирают. Родитель получает `KeyboardInterrupt`, и блок `finally`:
1) «хоронит» детей (`waitpid`), 2) удаляет сегмент `shared_memory`, 3) удаляет временную папку,
4) закрывает трубы. Код выхода — 130 (так принято для Ctrl+C). Также родитель обрабатывает
`SIGTERM` (команда `kill`) так же, как Ctrl+C.

**Как найден сбой?** Фоновые ошибки 5xx бывают всегда (~0,43% запросов). Сбой — это «густой»
всплеск: много ошибок с короткими паузами. `incident.py` собирает ошибки в цепочки и берёт
самые плотные (подробно — в докстринге скрипта).
